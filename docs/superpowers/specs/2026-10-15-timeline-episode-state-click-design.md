# 时间线单集状态与条目跳转修复

## 目标

修复时间线里单集记录的状态文案和条目跳转。播放到/读到某一集的动态应显示“看到”或相应的进行中状态，而完整作品状态仍显示“看过”；单集记录无论页面是否已成功解析出父条目 ID，都应能打开所属条目详情。

## 设计

- 解析章节动态时，以章节链接 `/subject/ep/{id}` 判断它是单集进度记录，不再因为描述中含“看过”就归类为已看完整作品。
- 状态标签使用“看到”，沿用时间线进度状态的颜色。若正文明确表示整部完成/收藏（例如作品级“看过 X”），继续显示“看过”。
- 在时间线模型中保留章节 ID。若加载阶段已取得父条目 ID，则直接用它打开条目详情；若未取得，点击时按章节 ID 查询章节 API 获取 `subject_id`，成功后导航。
- 若点击时父条目 ID 查询失败，给出可见错误反馈；不悄悄吞掉错误，也不导航到无效 ID。
- 普通条目动态继续使用既有的父条目 ID 点击行为；与多行合并、日期分组、状态导轨无关的逻辑保持不变。

## 验收

1. 时间线单集动态显示“看到”，整部作品完成/收藏动态仍显示“看过”。
2. 仅包含章节链接的动态可打开该章节所属条目的 App 详情；加载时已解析父条目的记录仍可直接打开。
3. 父条目查询失败时用户能看到失败提示，且 App 不崩溃。
4. `:app:assembleDebug` 构建成功，并安装到当前 Android 模拟器；在模拟器里验证上述状态和跳转后，将模拟器留给用户测试。

## 不在范围内

不调整时间线合并边界、日期表头、导轨动画/颜色、收藏状态请求，也不改章节页面或条目详情页本身。
