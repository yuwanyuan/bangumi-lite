# 浏览页与收藏页左右滑动切换

## 目标

为浏览页和收藏页增加左右滑动切换，让用户可在主要排序/状态间快速浏览，同时保留现有可点击筛选与加载方式。

## 浏览页

- 作品类型顺序沿用现有导航：动画、书籍、游戏、音乐、三次元。
- 横滑顺序为每种作品类型内依次“排名 → 热度 → 收藏”，完整序列共 15 个位置。例如动画排名 → 动画热度 → 动画收藏 → 书籍排名。
- 切换类型/排序时沿用现有 `selectedType` / `selectedSort` 与数据加载逻辑；切换到不同类型时默认排名。
- 现有“日期”排序 chip 保留可点击，但不属于横滑序列；选择日期后如发生横滑，进入所到类型对应的横滑排序（排名、热度或收藏）。
- 切换筛选时重置到内容顶部，避免沿用旧列表滚动位置。

## 收藏页

- 左右滑动仅循环三个主要状态：全部 → 看过 → 想看；反向顺序同理。
- 现有“在看、搁置、抛弃”等标签及作品类型二级筛选继续保留点击操作，但不纳入滑动序列。
- 由其他标签状态开始滑动时，向左/右进入序列中相邻的主要状态；边界不循环越界（全部左滑保持全部，想看右滑保持想看）。
- 切换仍使用现有收藏请求、加载和状态缓存流程；切换筛选时列表返回顶部。

## 手势范围与冲突处理

- 手势监听只放在两页的内容列表区域，不放在顶部 tab、排序 chip 或二级类型筛选行上，以免抢占筛选行的水平滚动。
- 只认明显以水平方向为主的拖动，避免与列表纵向滚动和收藏页下拉刷新冲突；一次手势最多切换一个相邻位置。
- 不新增 Pager 依赖；通过 Compose 指针手势识别消费有效的水平滑动并更新现有筛选状态。

## 验收

1. 浏览页可按动画排名→热度→收藏→书籍排名的顺序正反滑动，并继续覆盖所有类型；页面 chip/tab 与数据请求状态同步。
2. 日期排序仍可点击使用；顶部排序和类型 tab 可以正常水平滚动与点击。
3. 收藏页左右滑动只在全部、看过、想看三项间相邻切换；在看、搁置、抛弃与作品类型筛选仍可点击。
4. 垂直滚动/下拉刷新正常，不被误识别成水平切换；成功切换后内容列表回到顶部。
5. 构建成功，并在 Android 模拟器验证浏览和收藏手势。

## 不在范围内

不改变现有 API、分页策略、排序实现、收藏状态定义、底栏页面导航和筛选标签文案；不增加水平翻页动画或 Pager 库。
